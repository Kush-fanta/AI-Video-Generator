# Data Visualization

Data visualization is proof on screen.

For Varnam, charts and diagram beats are not decoration, dashboard residue, or filler between "real" visuals. They are often the clearest way to make a claim visible. This doc governs when data should take the frame and how it should behave when it does.

## First Principles

1. **One frame, one claim.** A chart is successful only if the viewer can say what it proved.
2. **Comparison is the default grammar.** Rank, delta, before/after, target/actual, part/whole, and change over time are the core moves.
3. **The hero fact must dominate physically.** If the key number or contrast is visually subordinate, the chart is lying about importance.
4. **Choose the simplest chart that makes the claim undeniable.** Use bars before novelty, slope before flourish, direct labels before legend-hunting.
5. **Label only what the viewer must read.** Remove anything that does not sharpen the comparison.
6. **Motion must explain change.** Reveals, counts, draws, and transitions should carry meaning, not just energy.
7. **Context belongs inside the proof.** Benchmarks, targets, prior states, and source stamps should be present when they are necessary to interpret the number honestly.
8. **Readability beats density.** If the viewer has to decode the frame, the chart is too smart for its job.

## Chart Selection Defaults

- **Ranking / magnitude** -> bars
- **Before vs after / target vs actual** -> dumbbell, paired bars, or split stat
- **Change over time** -> line, slope, or stepped progression
- **Part to whole** -> stack, waffle, or segmented bar
- **Mechanism / system flow** -> diagram, chain, or tracked object sequence
- **Single dominant fact** -> hero stat with just enough context to keep it honest

## Data Viz Tests

### Claim Test

Can the viewer state the exact point of the chart in one sentence?

### Eye-Test

Is it obvious what the viewer reads first?

### Honesty Test

Does the visual framing exaggerate or hide anything the argument depends on?

### Mobile Test

Would the key label, number, and contrast still read at reduced size?

### Motion Test

If the animation were removed, would the static chart still make sense?

## Failure Modes

Reject the data-viz beat if it becomes:
- dashboard wallpaper
- axis-and-grid clutter with no thesis
- decorative motion with no informational value
- tiny-label density that assumes pause-and-study behavior
- a chart type chosen for novelty rather than clarity
