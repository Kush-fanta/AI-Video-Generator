# Scripting

`story/script.md` is the spoken-and-written argument for the film.

For the Varnam harness, this doc is not a writing course. It is the control surface for turning story intent into narration, interview structure, and page-level argument. Keep the governing rules explicit, keep the defaults compact, and keep failure tests easy to apply under load.

## Purpose

The script must:
- create pressure to keep watching
- carry causation and abstract reasoning
- give the board something worth spending
- remain speakable as narration

The script is not the board, not the render manifest, and not a research memo.

## First Principles

1. **The script is spoken argument.** Write for one listen, not for page elegance.
2. **Pressure beats completeness.** The viewer needs the next reason to keep going, not all the background at once.
3. **Story enters through consequence.** Start with what is at stake, changing, breaking, or becoming unavoidable.
4. **Causation beats chronology.** Sequence matters only when it explains why one thing made the next thing true.
5. **Specificity creates belief.** Real names, places, scenes, and numbers beat generalized abstraction.
6. **The screen carries its share.** The script should say what the viewer cannot reliably infer from the image alone.
7. **A section must change state.** If nothing turns, sharpens, or becomes newly legible, it is not yet a section.

## Core Invariants

1. **Argument before information.** Facts matter only when arranged in support of a claim.
2. **Outer loop before exposition.** The viewer needs a question, tension, or paradox before they need background.
3. **Human stakes before system scale.** Long-form scripts need a person, scene, or concrete situation early enough to prevent lecture drift.
4. **Evidence earns implication.** Claims are strongest when the script gives the fact, then the consequence, then the interpretation.
5. **Write for the ear.** Sentences must sound natural when spoken once.
6. **Do not duplicate the screen.** The script should not narrate what the board can already prove visually.
7. **Every line changes pressure.** A line should escalate, reframe, reveal, or pay off. If it merely restates, cut it.

## Script Tests

The script is not ready unless it passes all of these:

### One-Sentence Test

Can the script's argument be stated in one sharp sentence?

### Why-Now Test

Does the viewer understand why this piece matters now rather than as generic background knowledge?

### Outer-Loop Test

Is there a clear question, tension, paradox, or unresolved pressure carrying the viewer forward?

### Human-Beat Test

For any script over 3 minutes, does a named person, concrete scene, or specific human situation appear in the first 40%?

### Speakability Test

Would the line make sense if heard once, with no reread?

### Visual Partnership Test

Does the script leave room for the board to do its work, or is it trying to describe the whole film in words?

### Cut Test

If you remove the line, does pressure drop? If not, cut it.

## Default Writing Pattern

Use this default unless the task clearly demands another shape:

1. **Opening pressure**
   Start with stakes, paradox, or consequence. Not context.

2. **Minimal orientation**
   Give only the background needed to understand the next reveal.

3. **Escalation**
   Move from surface explanation toward deeper cause, larger consequence, or sharper contradiction.

4. **Turn**
   A good script changes state. Something is revealed, reversed, deepened, or made unavoidable.

5. **Landing**
   End with consequence, agency transfer, or a closing image. Do not dissolve into summary.

## Default Long-Form Pattern

For longer work, the safest harness default is:
- hook
- context in motion
- conflict / escalation
- turn
- landing

Do not split “context” into its own long dead zone. Context should arrive as answer to questions the viewer already has.

## Sentence Rules

- one thought per sentence
- short clauses beat nested clauses
- proper nouns and concrete details beat categories
- contractions are usually better than formal prose
- hedging is expensive; use it only when precision truly requires it
- numbers need comparison, consequence, or framing
- pauses belong where the argument breathes, not where the writer runs out of grammar

## What The Script Carries

The script should carry:
- argument
- causation
- narrative connective tissue
- emotional stance
- what the viewer cannot infer from the image alone

The script should not carry:
- shot descriptions
- layout logic
- prompt packets
- main on-screen text payloads
- paragraphs that simply restate the visible evidence

## Relationship To Board And Manifest

- script: argument in spoken form
- board index: what kind of film this is
- scene boards: what the viewer experiences scene by scene
- render manifest: where those decisions land on the timeline

If the script is doing board-index work, it is bloated.
If the script is doing scene-board work, it is confused.

## Operating Defaults

- Prefer real names, real places, and real situations.
- Front-load pressure, not explanation.
- Backfill context only when it unlocks the next beat.
- Keep the first draft sharp enough that the board can discover a film, not rescue an essay.
- If duration overruns, cut prose before relying on voice speed.

## Advanced Patterns

Use these deliberately, not by default:

- **Reversal**: what seemed true is no longer true.
- **Scale oscillation**: alternate human detail with systemic scale.
- **Ironic gap**: narration says one thing while the eventual board proves a sharper truth.
- **Nested loops**: for long-form, smaller unresolved questions inside the main arc.
- **Agency transfer**: closing shifts the viewer from observation to consequence or leverage.

## Common Failure Modes

Reject or rewrite when the script becomes:
- **The lecture**: all information, no pressure
- **The rant**: all implication, no evidentiary spine
- **The info-dump opening**: context before stakes
- **The missing turn**: problem explained, nothing changes
- **The orphan statistic**: number with no frame
- **The even-handed mush**: conflict blurred into bland balance
- **The visual transcript**: narration duplicating what the viewer can already see

## Harness Rule

This doc should stay small enough that the model can hold the whole writing policy in working context.

If a new rule is not:
- generally reusable
- operationally testable
- more important than an existing rule

then it does not belong here.
